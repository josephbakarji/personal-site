Idea-to-Output Workflow

This page documents the typical workflow for turning ideas into outputs (papers, articles, prototypes, demos). It serves as a shared reference for both Joe and Claude across sessions.

The Pipeline

raw → exploring → prototype → draft → submittable → published
  • raw — Captured from voice memo, conversation, or brainstorm. Not yet explored.
  • exploring — Actively researching: reading related work, testing feasibility, gathering data.
  • prototype — Working code, initial results, proof of concept exists.
  • draft — Paper or article draft written. Content taking shape.
  • submittable — Polished enough to submit/publish. Final review.
  • published — Live on website, submitted to journal, or shipped.
  • parked — On hold. Not dead, but not actively being worked on.

Typical Session Flow

1. Capture (voice memo or conversation)

  • Record a voice memo while walking/thinking
  • Or start a Claude session and brainstorm
  • The dashboard shows recent voice memos with a + idea button

2. Create an Idea

  • From dashboard: click + New Idea or + idea on a voice memo card
  • From terminal: Claude can POST to /api/dashboard/ideas
  • Set initial stage to raw
  • Tag with relevant topics

3. Work on It (Claude sessions)

  • Open a Claude session in the relevant project directory
  • Each session gets a unique ID (visible in the dashboard under "Recent Sessions")
  • Link session IDs to ideas in the dashboard to track which sessions contributed
  • Advance the idea's stage as it progresses

4. Resume Work

  • Find the idea on the dashboard, see linked sessions
  • Click copy on any session to get the resume command:
claude --dangerously-skip-permissions --resume SESSION_ID
  • Or start a fresh session — Claude can read the dashboard to pick up context
  • Or use claude --continue to resume the most recent session

5. Produce Outputs

  • Paper: LaTeX draft in 00-projects/00-active/[project]/paper/
  • Article: Markdown in personal-site/content/articles/, registered in articles.json
  • Prototype: Code in project folder, tracked in nexus registry
  • Slides: RevealJS in teaching or project folder

Key Commands

Terminal (Claude Code)

claude                                  # new session in current dir
claude --continue                       # resume last session
claude --resume SESSION_ID              # resume specific session
claude --dangerously-skip-permissions --resume SESSION_ID  # resume, skip prompts

Voice Memos (from nexus)

python3 ~/Documents/05-nexus/tools/voice_memos.py recent 10    # recent memos
python3 ~/Documents/05-nexus/tools/voice_memos.py search "topic" # search by title
python3 ~/Documents/05-nexus/tools/voice_memos.py transcribe ID  # transcribe one

Dashboard API (for Claude or scripts)

# List ideas
curl http://localhost:5001/api/dashboard/ideas

# Create idea
curl -X POST http://localhost:5001/api/dashboard/ideas \
  -H 'Content-Type: application/json' \
  -d '{"title":"My idea","stage":"raw","tags":["topic"]}'

# Update idea stage
curl -X PUT http://localhost:5001/api/dashboard/ideas/my-idea \
  -H 'Content-Type: application/json' \
  -d '{"stage":"exploring"}'

# Get recent sessions
curl "http://localhost:5001/api/dashboard/sessions?limit=10"

Architecture

Everything runs on the personal-site admin backend (Flask, port 5001):

localhost:5001/admin/dashboard  → this dashboard
localhost:5001/admin/           → article CMS
localhost:5001/admin/workflow   → this page
localhost:5001/                 → site preview

Data sources aggregated by the dashboard:

  • Ideas: personal-site/data/ideas.json
  • Articles: personal-site/data/articles.json
  • Projects: Scanned from ~/Documents/00-projects/00-active/ and 01-tests/
  • Papers: Nexus registry at 05-nexus/skills/papers/registry.json
  • Voice Memos: Apple Voice Memos DB via voice_memos.py
  • Sessions: Claude JSONL files in ~/.claude/projects/
Phase 2 (next): Mirror app integration — proxy Mirror API to show transcripts inline, link memos to ideas automatically, clean up Mirror inefficiencies.

Conventions

  • Ideas are named with kebab-case slugs (e.g., action-conditioned-information)
  • Each idea can link to one project, one article, and one paper
  • Session IDs are UUIDs — store the full ID, use copy button for the resume command
  • Tags should be lowercase, hyphenated, reused across ideas when possible
  • The origin field tracks where the idea came from: voice-memo:ID, conversation, research, etc.
